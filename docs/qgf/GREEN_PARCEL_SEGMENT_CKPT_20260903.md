## 2. 切分点是怎么定的(以及为什么不是固定偏移)

### 先排除了固定规则

红段用的是 `[0, 红释放 + 7s]`,那个 7 秒是**尾巴**参数(松手后退开),不是起点参数。绿段的起点是新问题。

扫了两类锚点(50 条全量,按 HSV 检测绿包裹是否在画面内):

| 起点规则 | 胸部可见 | 腕部可见 | 起始位姿最宽极差 |
| --- | ---: | ---: | ---: |
| 红释放 + 0s | 66% | **0%** | 83.0° |
| 红释放 + 5s | 96% | 34% | 102.1° |
| 红释放 + 7s | 100% | 66% | 117.2° |
| 红释放 + 8s | 100% | **80%** | 108.4° |
| 绿抓取 − 6s | 100% | 72% | 103.1° |

**「红释放那一刻」在关节空间最集中(83°),但腕部相机 0/50 看得见绿包裹** —— 镜头对着刚放下的红包裹,完全背对箱子。按位姿集中度选会选出一个让模型闭眼开局的切点。这个判断是看图推翻的,不是算出来的。

### 最终采用:逐条自适应

固定 `红释放+8s` 仍有问题:起点距绿抓取的余量最短只有 **1.7 秒**,部分 episode 一开局就该闭夹爪,开局分布很不一致。

改为**每条单独挑**:在合法窗口 `[红释放, 绿抓取 − 6s]` 内(0.5s 网格)搜位姿最接近共同参考、且绿包裹可见的时刻;再用选出的 50 个位姿更新参考,迭代。**5 轮收敛,位移归零。**

参考位姿 J1..J7:`[-2.163, -0.242, 0.080, -1.839, -1.917, -0.231, 4.725]`

| | 固定 红释放+8s | 逐条自适应 |
| --- | ---: | ---: |
| 起始位姿最宽极差 | 108.4° | **102.4°** |
| 胸部可见 | 50/50 | **50/50** |
| 腕部可见 | 40/50 | **42/50** |
| 距绿抓取余量 | min **1.7s** | min **6.1s** |

**终点**:episode 自然结束,不截尾。

计划文件:`tools/green_parcel/green_adaptive_plan.json`(每条的 t0/t1/余量/胸腕可见度/距参考距离/位姿)。

### 诚实的边界

- 位姿极差只从 108° 降到 102°,提升有限。这些 episode 松手后手臂摆位本就分散,窗口内没有能让全部对齐的时刻;最远的 ep74 距参考 1.54 rad(88°),怎么挑都靠不拢。
- 优化目标是**位姿接近参考**,不是画面接近。腕部相机装在手腕上,同样关节角看到的东西可以差很多。
- 腕部相机**连「正在抓绿包裹」那一刻都只有 62% 能检出绿色**,是任务本身的视角限制(夹爪和箱壁遮挡),不是切分问题。绿 ckpt 会比红 ckpt 更依赖胸部相机。

## 3. 清洗:J5 的 2π 问题

这是本次明确要解决的问题。原始数据里 J5 存在**两个相差 2π 的分支**(19 条在 pos、31 条在 neg),纯粹取决于录制时机,导致同一个物理位姿在输入上表现为两个完全不同的值。

处理:全部按 ±2π 对齐到多数分支(neg),`j5_shift_rad = -6.283185`。这是**记录值的表示对齐,不是安全包络重写** —— 物理位姿未变,也未做任何 canonicalize。与红段清洗同一策略。

效果:

| | 清洗前 | 清洗后 |
| --- | ---: | ---: |
| 逐条 J5 均值极差 | **6.764 rad ≈ 2π** | **0.839 rad = 48.1°** |
| 全部样本极差 | — | 1.476 rad = 84.6° |
| 逐条均值最大间隙 | 5.683(双簇) | **0.108(单簇)** |

J5 现在与 J4/J6/J7 同量级(82–86°),就是关节真实活动范围。

### 与红段清洗的其它差异

红段从 episode 开头切到某处,时间戳天然从 0 开始;**绿段是从录制中间切的**,因此:

- `timestamp` 减去起点值,重新从 0 起算
- `frame_index` 重排为 0..n-1
- 视频用 `trim=start_frame=N,setpts=PTS-STARTPTS` 按**帧号**裁剪并重置显示时钟

> ⚠️ 视频必须按帧号裁而不是按时间戳:parquet 行与视频帧是 1:1,关键帧对齐造成的 off-by-one 会静默地让图像和状态错位。
>
> ⚠️ ffmpeg 7 里 `-r 30` 与 `-vsync 0` 互斥(报 "contradictory"),红段脚本那套参数在本机直接失败。`trim+setpts` 同时满足帧号精确、时钟归零、保持 30fps 恒定帧率。

## 8. 真机使用须知

### 场景摆放

绿段训练数据的每一帧都是「红包裹已在桌上、绿包裹在箱里」。真机测试前必须先摆成该状态。

### 初始位姿

绿段的起点不是固定 home 位,而是「刚放完红包裹之后」的姿态。参考位姿(50 条中位数):

| 关节 | 参考 | 训练见过的范围 | 中间 80% |
| --- | ---: | --- | --- |
| J1 | −123.9° | −168.1° ~ −91.6° | −146° ~ −103° |
| J2 | −13.9° | −48.7° ~ 6.3° | −29° ~ 0° |
| J3 | +4.6° | −35.4° ~ 67.0° | −20° ~ +31° |
| J4 | −105.4° | −124.6° ~ −82.1° | −117° ~ −92° |
| J5 | −109.9° | −125.3° ~ −85.7° | −119° ~ −97° |
| J6 | −13.3° | −37.0° ~ 10.2° | −33° ~ +6° |
| J7 | +270.7° | 251.2° ~ 301.6° | 256° ~ 294° |

最紧的 J4/J5 中间 80% 各有 22–25° 余地,拖拽到参考值 ±10° 即可。位姿不对时守卫会打印实际值与允许范围并拒绝启动,是安全的试错循环。

作为对照,红段真机启动时的允许包络 J1 宽 83.4°、J3 宽 81.4° —— 该系统本就按宽包络设计。

### 另一种测法

红 ckpt 跑完的终态正好是绿段的起始态(本就是同一条 episode 的两半),可以串联跑,免去手动摆位与摆红包裹。代价是绿段成功率会被红段失败拖累。建议先独立测拿到绿 ckpt 自身成功率,两个都稳后再串联测全流程。
